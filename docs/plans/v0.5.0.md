# Version 0.5.0 plan: stabilization

## Status

In progress and approved. This is the next public release after 0.4.0.

Already implemented on `main` but not yet released:

- Current `cmux sessions --json` lifecycle decoding with legacy fallback.
- The dedicated bounded Work board, compact Work overview, filters, and explicit no-live triage.
- Safe `Active -> Review` and `Review -> Active` automation for fresh high-confidence structured evidence.

Remaining before release:

- Hover and keyboard-focus polish.
- Compact horizontal attention and workflow-proposal presentation.
- Guarded `Review in cmux` plus foreground application activation.
- Reproduction and correction of the expanded cmux-list scrolling instability.
- Final automated, local-vault, screenshot, metadata, and release verification.

## Goal

Make the existing cmux observation, attention, and Work-board experience reliable enough to serve as the foundation for command delivery in 1.0.0.

Version 0.5.0 must improve clarity and interaction quality without expanding the plugin into a terminal controller.

## Scope

### Lifecycle compatibility

- Accept the current bounded `cmux sessions --json` lifecycle shape when legacy `list-agents` is unavailable.
- Retain compatibility with legacy snapshot-only cmux builds.
- Feature-detect live events instead of assuming a particular cmux version.
- Preserve `State unknown` whenever fresh, non-conflicting structured lifecycle evidence is unavailable.

### Work experience

- Keep the primary Work mode compact: attention first, followed by workflow totals.
- Open one reusable dedicated Work-board tab for detailed planning.
- Keep the board within the available view height.
- Give each workflow column its own vertical scroller and the column canvas a horizontal scroller.
- Preserve search, live-run filters, keyboard focus, selection, and scroll position across safe rerenders.
- Keep controls usable with long titles, narrow panes, zoomed text, light themes, and dark themes.

### Attention and review

- Replace the tall workflow-proposal panel inside a narrow task card with a compact horizontal attention row.
- Present the signal, proposed transition, and primary action without forcing sentence fragments into a narrow column.
- Provide a `Review in cmux` action for an exact linked run.
- Revalidate the current task revision, workflow, binding, cmux target, proposal, and source freshness immediately before applying the review transition.
- After a valid explicit review action, apply the pending `Active -> Review` transition, focus the exact cmux surface, and request foreground activation of the cmux application.
- Treat a partial result honestly: report workflow movement, cmux focus, and application activation as separate outcomes.
- Never infer a durable workflow transition merely because the user selected a tab directly inside cmux.

### Interaction polish

- Give task actions, including `Open task`, visible hover and keyboard-focus states using Obsidian theme variables.
- Prevent expanded cmux details and terminal previews from creating competing page-level scroll roots.
- Prevent refreshes from making the visible list jump, overlap sticky navigation, or lose the expanded item unexpectedly.
- Keep reduced-motion behavior and status communication that does not rely on color alone.

### Safe workflow behavior

- Keep Suggest as the default automation mode.
- Allow Safe auto only for fresh, high-confidence, structured `Active -> Review` and `Review -> Active` evidence.
- Keep Backlog activation suggestion-only.
- Keep Parked and Done fully human-controlled.
- Keep explicit no-live parking selection-based and revalidate surface absence before every write.

## Non-goals

- Sending text or key input to a terminal.
- Starting, resuming, interrupting, closing, or killing provider sessions.
- Running an AI coordinator.
- Broadcasting an action to several sessions.
- Reading complete provider transcripts.
- Automatically moving any task to Done.

## Implementation slices

1. Diagnose and fix hover, focus, and cmux-list scroll behavior.
2. Replace the card-sized proposal with the compact attention treatment.
3. Add the guarded `Review in cmux` compound action and foreground activation adapter.
4. Complete lifecycle compatibility and event feature detection.
5. Run unit, integration, static layout, and read-only live checks.
6. Install the production bundle in an isolated vault and complete manual acceptance testing.
7. Update screenshots, changelog, versions, and release notes only after acceptance passes.

Each slice should land as a focused commit with its own tests or verification evidence.

## Acceptance criteria

- A normally launched Obsidian instance connects through the documented cmux access mode.
- A fresh supported Codex or Claude run appears once with the strongest provable identity and lifecycle state.
- Missing or conflicting lifecycle evidence remains explicit rather than guessed.
- Work stays compact and opens exactly one dedicated board tab.
- The board remains bounded while columns and the canvas scroll independently.
- Hover and keyboard focus are visible on every action.
- A finished turn renders one compact attention treatment without broken narrow-column wrapping.
- `Review in cmux` cannot target a stale or reused surface.
- A successful review action moves only the intended task to Review, focuses only the intended surface, and brings cmux forward.
- Directly visiting a tab in cmux never marks a task Done or silently changes durable workflow.
- Refresh, reload, and repeated events create no duplicate task, run, binding, or proposal.
- Parked and Done remain protected from runtime automation.
- Disabling and re-enabling the plugin leaves every cmux and provider process running.

## Verification gate

```bash
npm ci
npm run check
npm run test:live:read-only
```

Manual verification must cover normal macOS launch, current cmux, legacy fixtures, narrow and wide panes, light and dark themes, keyboard navigation, a fresh provider turn, no-live review cancellation, exact review/focus, plugin reload, and duplicate prevention.

Release only after the development-vault bundle matches the repository artifacts and the manifest, package, versions map, changelog, screenshots, tag, and release assets all identify 0.5.0 consistently.
